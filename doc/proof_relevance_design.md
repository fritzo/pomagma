# Computing Proof Relevance in E-graphs

## Objective

Extend E-graph occurrence counting to compute relevance weights for E-classes based on their usefulness in proving goal inequalities in ordered combinatory algebras.

## Background

In ordered combinatory algebras, we work with a Scott information ordering `x ⊑ y` (read "x approximates y") between programs. An E-graph represents equivalence classes of terms, but we also need to reason about inequalities between E-classes. Given a set of goal statements like `m ⊑ n` or `m ⋢ n` (not less than), we want to compute which E-classes are most relevant for proving these goals.

This generalizes standard occurrence counting: while occurrence counting weights E-classes by how often they appear as subterms, proof relevance weights them by how useful they are in constructing proofs. An E-class might be relevant even if it never appears as a subterm of the goal, as long as it helps establish the inequality through transitivity or other inference rules.

## Design Overview

Given an E-graph structure and a set of weighted goal statements $G = \{(g_i, w_i)\}$ where each $g_i$ is either `m ⊑ n` or `m ⋢ n`, we compute relevance weights $R[i]$ for each E-class $i$ by backward-chaining through possible proofs. The algorithm iterates:

$$R[i] = \sum_{g \in G} w_g \cdot \mathbb{1}[i \in g] + \sum_{\text{rules}} \sum_{\substack{\text{conclusions } c \\ \text{using } i}} \frac{P[\text{rule}] \cdot P[i] \cdot R[c]}{Q[c]}$$

where $P[i]$ is the E-class probability from the PCFG, $Q[c] = \frac{1}{2}(P[c] + P[\neg c])$ is the query complexity, and the sum ranges over inference rules that use E-class $i$ to derive relevant conclusions $c$.

## Design Details

### Proof Language

Pomagma's inference system works with three primary operations: application (APP, `f x`), composition (COMP, `f∘g`), and join (JOIN `x|y`). The core inference rules for Scott ordering (LESS, `⊑`) are:
```
                              x ⊑ y   y ⊑ z             x ⊑ z   y ⊑ z
───────   ───────   ───────   ─────────────   ───────   ─────────────
x ⊑ x     BOT ⊑ x   x ⊑ TOP       x ⊑ z       x ⊑ x|y      x|y ⊑ z

  f ⊑ g       x ⊑ y       f ⊑ g       x ⊑ y
─────────   ─────────   ─────────   ─────────
f x ⊑ g x   f x ⊑ f y   f∘x ⊑ g∘x   f∘x ⊑ f∘y
```

Negative rules (NLESS, `⋢`) are automatically generated by negating the positive rules above.

### Probability Propagation Algorithm

The relevance computation generalizes the forward probability propagation by running it in reverse. We maintain relevance density $D[s] = R[s]/Q[s]$ for each statement $s$ (either `i ⊑ j` or `i ⋢ j`) and iterate until convergence.

For positive statements `u ⊑ v`, the relevance density accumulates contributions from all rules that could use this fact:

$$D[u ⊑ v] = D_0[u ⊑ v] + \sum_{\text{downstream uses}} \text{contribution}$$

where $D_0[u ⊑ v]$ is nonzero only if `u ⊑ v` is a goal. The downstream contributions come from:

1. **Transitivity**: If `u ⊑ v` helps prove `x ⊑ v` via `x ⊑ u`, then:
   $$\text{contribution} = P_{\text{trans}} \cdot P[x ⊑ u] \cdot D[x ⊑ v]$$

2. **Application monotonicity**: If `u ⊑ v` helps prove `u x ⊑ v x` or `x u ⊑ x v`, then:
   $$\text{contribution} = P_{\text{app}} \cdot P[x] \cdot D[u x ⊑ v x]$$

3. **Composition monotonicity**: If `u ⊑ v` helps prove `u∘x ⊑ v∘x` or `x∘u ⊑ x∘v`, then:
   $$\text{contribution} = P_{\text{comp}} \cdot P[x] \cdot D[u∘x ⊑ v∘x]$$

4. **Join propagation**: If `u ⊑ v` helps prove `u|x ⊑ v|x`, then:
   $$\text{contribution} = P_{\text{join}} \cdot P[x] \cdot D[u|x ⊑ v|x]$$

The algorithm maintains separate relevance for positive statements $D^+[i,j]$ and negative statements $D^-[i,j]$. After computing statement relevances, we aggregate to E-class relevances:

$$R[i] = \sum_j (D^+[i,j] \cdot P[i ⊑ j] + D^+[j,i] \cdot P[j ⊑ i] + D^-[i,j] \cdot P[i ⋢ j] + D^-[j,i] \cdot P[j ⋢ i])$$

### Choosing Goal Statements

In practice, choosing effective goal statements is crucial for directing the E-graph search toward useful discoveries. Consider the task of finding simple classifiers that fit training data while generalizing well. Given a data type with closure operator `type_data` and training examples `x₁, x₂, ..., xₙ`, we seek classifiers `f : type_data → {BOT, I, TOP}` that accept all training data while minimizing complexity and entropy.

Rather than directly searching for such classifiers, we can choose goal statements that make relevant the E-classes useful for constructing and analyzing them. An effective strategy combines three types of goals:

**Training data characterization**: For each training example `xᵢ`, include the goal `type_data xᵢ ⊑ xᵢ` with high weight. This ensures that E-classes representing projections, characteristic functions, and other operations that help identify training data become relevant. Additionally, for the join of all training data `training_set = x₁ | x₂ | ... | xₙ`, include goals like `training_set ⊑ type_data` to establish it as a valid subset.

**Interval refinement**: For promising interval bounds `[lb, ub]` discovered during search, add goals `lb ⊑ training_set` and `training_set ⊑ ub`. This makes relevant the E-classes that help tighten bounds around the training data, naturally leading to abstract interpretation via lattice intervals. The weights on these goals can decrease as intervals become larger, focusing effort on tight bounds.

**Entropy estimation**: To help estimate `entropy(f) = log |{x : type_data | f x = I}|`, include goals of the form `simple_predicate ⊑ type_data` for various simple predicates that might bound acceptance sets. For instance, if `even` and `odd` partition a discrete type, then proving `even ⊑ type_data` helps bound entropy. Weight these goals by their potential information gain.

The beauty of this approach is that the E-graph doesn't need special machinery for intervals or entropy calculation. By choosing goals that make certain inequalities important to prove, we automatically make relevant the E-classes that participate in those proofs—whether they represent interval endpoints, characteristic functions, or counting arguments. The proof relevance computation then identifies which terms are worth expanding in the E-graph to make progress on our machine learning task.

### Implementation Considerations

The fixed-point iteration converges when relevance flows from goals through all possible proof paths. Unlike forward probability propagation which flows from atoms to compounds, relevance for positive proofs flows toward subterms (following the direction that monotonicity rules decompose compounds), while relevance for negative proofs flows toward compounds.

To ensure convergence, initialize all relevances to zero except for goal statements, then iterate the propagation equations. The iteration can be accelerated using the same warm-starting techniques as probability propagation, maintaining relevance values between iterations and only updating changed entries.

The rule probabilities $P_{\text{trans}}, P_{\text{app}}, P_{\text{comp}}, P_{\text{join}}$ can be uniform or tuned to match the expected proof structure. In practice, transitivity rules often dominate, suggesting higher weight for $P_{\text{trans}}$. 

Join operations create additional complexity since `x|y` represents the least upper bound of `x` and `y`, making relevance flow bidirectionally between join expressions and their arguments. Special attention is needed for join distributivity rules like `(f|g) x = f x | g x`, which create complex relevance dependencies between application and join operations.
