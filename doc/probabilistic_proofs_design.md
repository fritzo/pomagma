# Design Doc: Probabilistic Proofs

## Objective

Extend E-graph probability propagation to (i) provide [0,1]-valued soft estimates for boolean queries whose truth values are unknown, and (ii) compute relevance weights for E-classes and atomic facts based on their usefulness in proving goal statements in ordered combinatory algebras.

## Background

In ordered combinatory algebras, we work with a Scott information ordering `x ⊑ y` (read "x approximates y") between programs. An E-graph compactly represents equivalence classes of terms through E-nodes of the form `APP f x = y`, but we also need to reason about atomic facts like inequalities `LESS x y` between E-classes. 

This design generalizes E-graph probability propagation from E-classes to atomic facts. While standard E-graph algorithms compute probabilities and occurrences for E-classes, we extend these to handle arbitrary atomic statements including both equalities (E-nodes) and inequalities. This enables two complementary algorithms:

**Forward propagation** computes proof complexity—the probability mass of all proofs of a statement—providing soft [0,1] estimates for queries whose truth values are unknown. This generalizes E-class probability computation to handle statements about ordering relationships.

**Backward propagation** computes proof relevance—how useful each atomic fact is for proving goal statements. This generalizes E-class occurrence counting to identify which facts and E-classes are worth exploring to make progress on specific queries.

## Design Overview

The system maintains two complementary measures for each atomic fact $\phi$ (whether equality or inequality):

**Proof complexity** $P[\phi]$ quantifies the total probability mass of all proofs of $\phi$, computed by forward propagation from axioms through inference rules. For queries with unknown truth values, this provides a [0,1] estimate of confidence. The query complexity $Q[\phi] = \frac{1}{2}(P[\phi] + P[\neg\phi])$ measures the difficulty of resolving the query either way.

**Proof relevance** $R[\phi]$ quantifies how useful $\phi$ is for proving goal statements, computed by backward propagation from goals through inference rules. Given weighted goals $G = \{(g_i, w_i)\}$, the relevance density $D[\phi] = R[\phi]/Q[\phi]$ iterates:

$$D[\phi] = D_0[\phi] + \sum_{\text{rules}} \sum_{\substack{\text{conclusions } \psi \\ \text{using } \phi}} P[\text{rule}] \cdot \frac{P[\phi]}{Q[\phi]} \cdot D[\psi]$$

These measures reduce to standard E-graph algorithms when restricted to reflexivity facts `x ⊑ x`: proof complexity becomes E-class probability, and relevance becomes occurrence counting.

## Design Details

### Proof Language

Pomagma's inference system works with three primary operations: application (APP, `f x`), composition (COMP, `f∘g`), and join (JOIN `x|y`). The core inference rules for Scott ordering (LESS, `⊑`) are:
```
                              x ⊑ y   y ⊑ z             x ⊑ z   y ⊑ z
───────   ───────   ───────   ─────────────   ───────   ─────────────
x ⊑ x     BOT ⊑ x   x ⊑ TOP       x ⊑ z       x ⊑ x|y      x|y ⊑ z

  f ⊑ g       x ⊑ y       f ⊑ g       x ⊑ y
─────────   ─────────   ─────────   ─────────
f x ⊑ g x   f x ⊑ f y   f∘x ⊑ g∘x   f∘x ⊑ f∘y
```

Negative rules (NLESS, `⋢`) are automatically generated by negating the positive rules above.

### Forward Propagation: Computing Proof Complexity

Forward propagation computes the proof complexity $P[\phi]$ for each atomic fact by accumulating probability mass from all possible proofs. Starting from axioms and the E-graph structure, we iterate:

$$P[u ⊑ v] = P_0[u ⊑ v] + \sum_{\text{rules}} \sum_{\text{premises}} P[\text{rule}] \cdot P[\text{premises}]$$

The base probabilities $P_0$ come from:
- **Reflexivity**: $P_0[x ⊑ x] = P_{\text{refl}} \cdot M[x]$ where $M[x]$ is the E-class mass from the PCFG
- **Constants**: $P_0[\text{BOT} ⊑ x] = P_{\text{bot}} \cdot M[x]$ and $P_0[x ⊑ \text{TOP}] = P_{\text{top}} \cdot M[x]$
- **E-graph facts**: $P_0[\phi] = P_{\text{db}}$ if $\phi$ is already proven in the E-graph

The propagation rules mirror the inference system:
1. **Transitivity**: $P[x ⊑ z] \mathrel{+}= P_{\text{trans}} \cdot P[x ⊑ y] \cdot P[y ⊑ z]$
2. **Application monotonicity**: $P[f x ⊑ g x] \mathrel{+}= P_{\text{app}} \cdot P[f ⊑ g] \cdot M[x]$
3. **Join rules**: $P[x ⊑ x|y] \mathrel{+}= P_{\text{join}} \cdot M[x] \cdot M[y]$

This generalizes E-class probability: when restricted to reflexivity facts $P[x ⊑ x]$, the algorithm reduces to standard PCFG probability computation over the E-graph.

### Backward Propagation: Computing Proof Relevance

Backward propagation computes relevance by flowing importance from goal statements back through potential proof paths. We maintain relevance density $D[\phi] = R[\phi]/Q[\phi]$ and iterate:

For each statement `u ⊑ v`, relevance accumulates from goals and downstream uses:

$$D[u ⊑ v] = D_0[u ⊑ v] + \sum_{\text{downstream uses}} \text{contribution}$$

where $D_0[u ⊑ v] = w_g/P[u ⊑ v]$ if `u ⊑ v` is a goal with weight $w_g$, and zero otherwise. Contributions flow backward through inference rules:

1. **Transitivity**: If `u ⊑ v` helps prove `x ⊑ v` via `x ⊑ u`:
   $$\text{contribution} = P_{\text{trans}} \cdot P[x ⊑ u] \cdot D[x ⊑ v]$$

2. **Application monotonicity**: If `u ⊑ v` helps prove `u x ⊑ v x`:
   $$\text{contribution} = P_{\text{app}} \cdot M[x] \cdot D[u x ⊑ v x]$$

3. **Join propagation**: For goals involving joins, relevance flows to both arguments

After computing statement relevances, we aggregate to E-class relevances:
$$R[i] = \sum_j D^+[i,j] \cdot P[i ⊑ j] + D^+[j,i] \cdot P[j ⊑ i] + D^-[i,j] \cdot P[i ⋢ j]$$

This generalizes occurrence counting: when goals are restricted to reflexivity facts, the algorithm counts how often each E-class appears in derivations of goal E-classes.

### Probabilistic Queries

When the E-graph cannot definitively prove or disprove a query `φ`, the proof complexity $P[φ]$ provides a soft [0,1] estimate of its truth. This probabilistic interpretation arises from viewing incomplete theorem proving as quantifier alternation:

For a universal query like "does `f` preserve property `P`?", expressed as `∀x. P x ⊑ P (f x)`, we accumulate evidence by checking instances. The proof complexity estimates:
$$P[∀x. P x ⊑ P(f x)] ≈ \prod_{x \text{ tested}} P[P x ⊑ P(f x)]^{M[x]}$$

where $M[x]$ weights instances by their probability under the PCFG. This gives high confidence when the property holds for all tested cases, especially probable ones.

For existential queries like "is there an `x` where `f x = g x`?", we take the dual approach:
$$P[∃x. f x = g x] ≈ 1 - \prod_{x \text{ tested}} (1 - P[f x = g x])^{M[x]}$$

This increases toward 1 as we find more evidence of equality, weighted by instance probability.

The query complexity $Q[φ] = \frac{1}{2}(P[φ] + P[¬φ])$ measures how close we are to resolving the query. When $Q[φ] ≈ 1$, we have strong evidence for a definite answer; when $Q[φ] ≈ 0$, the query remains unresolved despite our search efforts.

These probabilistic estimates enable practical reasoning about undecidable queries. Rather than giving up when a query cannot be proven, we provide calibrated confidence estimates based on accumulated evidence, allowing downstream systems to make informed decisions under uncertainty.

Applications range from program synthesis (where goals might characterize training data constraints) to abstract interpretation (where interval bounds become goals to tighten). The key insight is that strategic goal selection makes relevant the E-classes and atomic facts most useful for the downstream task, without requiring specialized machinery beyond the general probabilistic proof framework.

### Implementation Considerations

Both algorithms use fixed-point iteration but with opposite information flow directions. **Forward propagation** builds proof complexity from axioms outward, while **backward propagation** flows relevance from goals inward through supporting facts.

**Convergence properties**: Forward propagation converges when all derivable inequalities reach stable probability mass. Backward propagation converges when relevance has flowed through all possible proof paths from goals. Both can be accelerated using warm-starting—maintaining values between iterations and updating only changed entries.

**Data structures**: The algorithms require sparse matrices indexed by pairs of E-classes for inequality statements `LESS i j`, plus mappings from E-graph facts to probability masses. Forward propagation benefits from efficient enumeration of rule instances, while backward propagation needs efficient reverse lookup of which rules use each premise.

**Rule probabilities**: The weights $P_{\text{trans}}, P_{\text{app}}, P_{\text{comp}}, P_{\text{join}}$ can be uniform or tuned. In practice, transitivity often dominates since it enables long proof chains. Join operations create bidirectional dependencies that require careful handling in both directions—forward propagation must handle multiple ways to derive join inequalities, while backward propagation must split relevance among join arguments.

**Computational complexity**: Forward propagation has complexity $O(|E|^3 \cdot I)$ where $|E|$ is the number of E-classes and $I$ is iterations to convergence, dominated by the transitivity rule which examines all triples. Backward propagation has similar complexity but with different access patterns. Both can be optimized by maintaining changed sets and processing only affected statements each iteration.

**Integration with E-graph algorithms**: The framework extends existing E-graph probability computation and occurrence counting algorithms. When restricted to reflexivity facts `x ⊑ x`, forward propagation reduces to standard PCFG probability computation, and backward propagation reduces to occurrence counting. This enables gradual adoption—existing E-graph implementations can be extended to handle inequalities incrementally.
